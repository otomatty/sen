# GitHub 連携

チーム 1 つと GitHub のリポジトリ 1 つを対応させます。

課題と Issue を双方向に同期します。

プルリクエストを課題に紐づけて、ステータスを前へ進めます。

連携されるのは、Sen を運用する人が決めた 1 つのワークスペースだけです。

それ以外では、設定画面にこの区画は出ません。

## 何ができるか

| 項目 | 向き |
| --- | --- |
| タイトル | 双方向 |
| 説明 | 双方向 |
| 開閉と閉じた理由 | 双方向。完了とキャンセルだけが、GitHub の closed に対応します |
| コメント | 追加だけ、双方向 |
| ラベル | 同じ名前だけ、双方向 |
| 担当者 | GitHub のユーザー名を登録したメンバーだけ、双方向 |
| 優先度・見積もり・サイクル・プロジェクト・期日・親子・課題どうしの関係 | Sen だけ |

Sen で添付した画像は、GitHub では表示されません。

リンクは Sen で開き、そのワークスペースのメンバーなら見られます。

### 開閉

Sen で種類が完了になると、Issue を閉じます（`completed`）。

名前が「重複」のキャンセルは `duplicate` で閉じます。

ほかのキャンセルは `not_planned` で閉じます。

進行中・未着手・バックログは、開いたままです。

完了やキャンセルから戻すと、開き直します。

GitHub で閉じた理由が `completed` のとき、または `not_planned` でも `duplicate` でもないときは、そのチームの完了の最初のステータスになります。

`not_planned` はキャンセルの最初です。

`duplicate` は、種類がキャンセルで名前が「重複」のステータスがあればそれです。

無ければ、キャンセルの最初です。

開き直したときは、Sen が完了かキャンセルのときだけ、未着手の最初に戻します。

### ラベル

ラベルは、大文字小文字を区別しません。

両方にある名前だけを行き来します。

片方にしか無いラベルは残します。

どちらの側でも、ラベルは自動で作りません。

### 担当者

担当者は、プロフィールに GitHub のユーザー名を登録したメンバーだけです。

GitHub にだけいる担当者は残します。

その人を担当者にできないと GitHub が返したときは、担当者を外して送り直します。

課題の画面に理由を出します。

### 課題の詳細

課題の詳細には、チームが連携しているか、プルリクエストの紐づけがあるとき、GitHub の区画が出ます。

紐づいた Issue（`owner/repo#12`）のリンク、最終同期、失敗した理由が出ます。

ここから「GitHub に Issue を作る」「既存の Issue と紐づける」「紐づけを外す」ができます。

既存の Issue は、番号、`owner/repo#番号`、Issue の URL で指定します。

Sen と GitHub のどちらに合わせるかを選びます。

紐づけを外しても、GitHub 側は変わりません。

履歴には「〈名前〉が GitHub に owner/repo#12 を作りました」などと残ります。

「GitHub 経由」と出ます。

### プルリクエスト

プルリクエストは、番号・タイトル・状態（下書き、レビュー待ち、マージ済み、閉じた）・作者が並びます。

状態で、課題のステータスを自動で進めます。

初期値は、下書きが進行中の最初です。

レビュー待ちは「レビュー中」です。「レビュー中」が無ければ、進行中の最初です。

マージは、完了の最初です。

マージせずに閉じたときは、動かしません。

チームごとに、別のステータスか「変えない」を選べます。

課題のチームが連携していなければ、プルリクエストは見えますが、ステータスは動きません。

## 決まりごと

前回同期した値から、Sen と GitHub の両方が別の値に変わった項目は、Sen を残します。

説明が両方で変わったときは、GitHub 側の説明を Sen のコメントに残します。

文は「GitHub 側の説明と同時に変わったため、Sen の説明を残しました。GitHub 側の説明は次のとおりです。」です。

続けて、GitHub 側の本文そのものを書きます。

このコメントも GitHub に送られます。

自動で同期するのは、連携したあとに作られた課題と Issue だけです。

それより前のものは、課題の画面から 1 件ずつ紐づけます。

プルリクエストは、課題としては取り込みません。

コメントの編集と削除は、同期しません。

Sen のコメントは、トークンの持ち主のアカウントで投稿されます。

本文の先頭に `**〈Sen での名前〉**（Sen）` と空行が付きます。

末尾には、戻ってきた自分の投稿だと分かる印（`<!-- sen:comment:… -->`）が付きます。

GitHub から来たコメントでは、`@名前` をメンションとして検出しません。

購読している人へのコメント通知は出します。

書いた人の GitHub ユーザー名を登録したメンバーがいれば、その人のコメントになります。

いなければ、名前の代わりに「@ユーザー名（GitHub）」と出します。

プルリクエストでステータスを進めた履歴は、PR の作者の GitHub ユーザー名を登録したメンバーの操作になります。

登録が無ければ、リポジトリを連携した管理者です。

その人がメンバーでなくなっていれば、ワークスペースの管理者のうち最初の 1 人です。

課題の項目を GitHub から反映した履歴と、GitHub の Issue から課題を作った履歴は、その操作をした人の GitHub ユーザー名を登録したメンバーの操作になります。

登録が無ければ、同じ管理者です。

送り手が分からないとき（毎日の突き合わせなど）は、この管理者の操作になります。

GitHub で Issue が削除された、または別のリポジトリへ移されたときは、紐づけを外し、履歴に残します。

Sen で課題をアーカイブしても、GitHub には送りません。

Issue は閉じません。

アーカイブした課題は、新しく紐づけられません。

課題を別のチームへ移しても、紐づけは残ります。

元のリポジトリとの同期は続きます。

プルリクエストによる移動は、今より後ろへだけです。

順は、バックログ、未着手、進行中（同じ種類の中は並び順）、完了です。

キャンセルの課題は動かしません。

毎日 3 時ごろに、Webhook の取りこぼしを補います。

前回からあとに変わった Issue、コメント、プルリクエストを取り直します。

## PR を紐づける書き方

ブランチ名、タイトル、本文から課題を探します。

- ブランチ名。`user/eng-12` のように、チームの識別子と番号が入っていれば紐づきます。課題を開いて ⌘Shift+. を押すと、この形をコピーできます。メールアドレスの @ より前、チームの識別子、番号です。
- タイトルと本文の課題 ID。`ENG-12` のように、そのワークスペースのチームの識別子と番号です。大文字小文字は区別しません。
- 同期している Issue への参照。`#34`、`Fixes #34`、`owner/repo#34` です。`Closes` や `Resolves` が前にあっても同じです。`#34` は、プルリクエストと同じリポジトリの Issue です。
- コードブロックと行内のコードは見ません。

本文から参照が消えても、ブランチ名に残っていれば紐づけは残ります。

どの参照も無くなれば、そのプルリクエストの紐づけは外れます。

## 設定のしかた

GitHub のアクセストークンと Webhook の secret は、Sen を運用する人が Worker に設定します。

詳しい手順は、リポジトリ直下の README の「GitHub 連携」にあります。

設定 → ワークスペース の「GitHub 連携」で、管理者がチームにリポジトリ（`owner/name`）を連携します。

Webhook は自動で作られます。

作れないときは、画面に手での手順が出ます。

Issues が無効なリポジトリは連携できません。

各メンバーが、設定 → プロフィール の「GitHub のユーザー名」で、自分の GitHub のユーザー名を登録します。

他人の分は登録できません。

ほかのメンバーがすでに登録したユーザー名は登録できません。小文字で保存します。

空にすると登録が消えます。

必要なら、チームごとにプルリクエストの自動の移動を変えます。

下書き、レビュー待ち、マージの 3 つで、ステータスか「変えない」を選び、「自動の移動を保存」を押します。

管理者だけが変えられます。

課題の紐づけは、メンバーならできます。

連携を外すと、そのリポジトリの課題とプルリクエストの紐づけを消します。

自動で作った Webhook も消します。

Webhook を消せなくても、連携は外れます。

GitHub の Issue と Sen の課題そのものは消しません。

## 制限

- チーム 1 つに、リポジトリ 1 つです。同じリポジトリを、別のチームには連携できません。
- 優先度、見積もり、サイクル、プロジェクト、期日、親子、課題どうしの関係は同期しません。
- GitHub の Projects は対象外です。
- 連携できるのは、Sen を運用する人が決めた 1 つのワークスペースだけです。
